# Releasing umh-core

## Overview

All development happens on `staging`, and releases are cut from it: create a GitHub Release that targets `staging`. Creating the Release also creates the git tag, which triggers all downstream automation. The `main` branch is no longer used.

## Changelog convention

`CHANGELOG.md` is generated by [changie](https://changie.dev). Never edit it by hand. During development, each PR adds a fragment to `.changelog/unreleased/` with `make changelog`. At release time, `make release-changelog VERSION=X.Y.Z` moves all fragments into `.changelog/X.Y.Z.md` and regenerates `CHANGELOG.md` with a `## [X.Y.Z]` section. The version number is still decided at release time.

## Pre-release (nightly)

1. Go to [Releases > Draft a new release](https://github.com/united-manufacturing-hub/united-manufacturing-hub/releases/new)
2. Create a **new tag** with the format `v0.X.Y-pre.N` (e.g., `v0.44.10-pre.1`)
3. Target: `staging`
4. Check **"Set as a pre-release"**
5. Body can be minimal — pre-releases don't get changelog sync or release notes automation
6. Click **Publish release**

### What happens automatically

| Workflow | Trigger | What it does |
|----------|---------|-------------|
| `build-umh-core.yml` | tag push | Builds Docker image, pushes to GHCR, verifies binaries, notifies MC webhook with `channel: nightly` |

## Stable release

1. On a branch off `staging`, run `make release-changelog VERSION=0.44.12` in `umh-core/` (no `v`; a leading `v` is stripped). Review the new `.changelog/0.44.12.md` and the `CHANGELOG.md` diff, open a PR to `staging` and merge it. Tag right after: a PR merged in between leaves a fragment in `.changelog/unreleased/` that misses this release's notes.
2. Go to [Releases > Draft a new release](https://github.com/united-manufacturing-hub/united-manufacturing-hub/releases/new)
3. Create a **new tag** with the format `v0.X.Y` (e.g., `v0.44.10`) — no `-pre.` suffix
4. Target: `staging`
5. Release name (title): the version only, e.g. `v0.44.12`. The changelog.umh.app entry uses it as its title.
6. Body (optional): paste the CHANGELOG.md section for this version as a fallback. Automation will overwrite it with a formatted version including the changelog.umh.app link. If automation fails, the original body is preserved.
7. Do NOT check "Set as a pre-release"
8. Click **Publish release**

### What happens automatically

| Workflow | Trigger | What it does |
|----------|---------|-------------|
| `build-umh-core.yml` | tag push | Builds Docker image, pushes to GHCR, verifies binaries, notifies MC webhook (see promotion logic below) |
| `sync-changelog.yml` | release published | Extracts version section from CHANGELOG.md, creates PR on [changelog.umh.app](https://github.com/united-manufacturing-hub/changelog.umh.app) |
| `update-github-release.yml` | release published | Extracts version section from CHANGELOG.md, overwrites the GitHub Release body, appends changelog.umh.app link. Fails if `.changelog/X.Y.Z.md` is missing or empty, or if `.changelog/unreleased/` still holds fragments at the tag |
| `linear-release.yml` | release published | Creates the Linear release, attaches the ENG issues in the commit range, and sets its description from the CHANGELOG.md section |

### MC webhook promotion logic

When notifying Management Console of a stable release:

- If the current nightly's base version matches the stable tag (e.g., nightly `v0.44.10-pre.3` → stable `v0.44.10`), the nightly is **promoted** to stable
- Otherwise, a new stable version entry is created directly

Both staging and production MC instances are notified.

## Post-release checklist

- [ ] Verify the Docker image is available: `docker pull ghcr.io/united-manufacturing-hub/umh-core:v0.X.Y`
- [ ] Verify the GitHub Release body was updated with CHANGELOG.md content
- [ ] Verify `sync-changelog.yml` merged its changelog.umh.app PR (the changelog link in the GitHub Release is a 404 until then)
- [ ] Verify MC shows the new version (check both staging and production)
- [ ] Verify the "Check the changelog is cut" step of `update-github-release.yml` passed

## Troubleshooting

### GitHub Release body is empty or wrong
Check the `update-github-release.yml` run in the Actions tab. Common cause: `make release-changelog` was not run and merged before tagging, so the version section is missing (shows as warning in the workflow summary). Re-run via Actions > Update GitHub Release > Run workflow > enter the tag name.

### Fragments left in `.changelog/unreleased/` at the tag
A PR merged after the release-changelog PR. Its change ships in this release but is not in the release notes. `changie batch` cannot add it, because it refuses an existing version file. On a branch off `staging`, copy each fragment's entry into `.changelog/X.Y.Z.md` under its section, delete the fragments, run `make rebuild-changelog`, and merge the PR with the `skip-changelog-guard` label. Then add the entries to the GitHub Release body and the changelog.umh.app entry by hand.

### Fixing a released entry
Edit `.changelog/X.Y.Z.md`, run `make rebuild-changelog`, and commit both files. The released-section guard in PR CI rejects the change, so add the `skip-changelog-guard` label.

### changelog.umh.app entry was not created
Re-trigger via Actions > Sync Changelog > Run workflow > enter the version. Supports `dry_run` mode for testing.

### Docker image was not pushed
Check the `build-umh-core.yml` run. If the build job failed, the tag still exists. Fix the issue and re-run the workflow from the Actions tab.

### MC was not notified of new version
Check the `notify-management-console` job in the `build-umh-core.yml` run. The webhook can be re-sent by re-running that job.

## Workflow files

| File | Purpose |
|------|---------|
| `.github/workflows/build-umh-core.yml` | Build, verify, notify MC |
| `.github/workflows/sync-changelog.yml` | Sync CHANGELOG.md to changelog.umh.app |
| `.github/workflows/update-github-release.yml` | Populate GitHub Release body from CHANGELOG.md, check the changelog is cut |
| `.github/workflows/linear-release.yml` | Sync the release to Linear |
| `.github/workflows/pull-request.yml` | PR CI (calls build-umh-core.yml as reusable workflow) |
