# Product Features and Supported Paths

For some jobs, UMH Core offers more than one way to get them done. This page says which way we intend you to use, and what we promise about each of the others, so that you can tell a way we will keep working from one you may have to move off later.

Every page that names a component or a part of one says whether it is a product feature, an early access feature, a supported path or a provisional path, so you do not have to come back here to find out. A guide or a troubleshooting page below it has the same status as the component it belongs to.

## Product features

A product feature is the intended way to do something. It has its place in the Management Console, UMH Core checks what you give it, we keep building on it, and you can ask us to change it.

Most of this documentation describes product features.

## Supported paths

A supported path is a documented way to do a job that no product feature covers.

We keep a supported path working, and we fix faults in it. We do not extend it: it gets no new screens in the Management Console and no new options.

If a supported path is not enough for what you need, [tell us](get-help.md) what you are trying to do. We can act on that as a request for the product feature that would do the job.

When such a feature ships, the supported path keeps working. You decide whether and when to move to the feature.

## Provisional paths

A provisional path works today and may change. If it changes, you may have to move your setup to something else.

Use a provisional path when you need it, and [tell us](get-help.md) when you do, so that we know who to warn. Where we already know what will end one, the page that describes it says so.

## Escape hatches

An escape hatch is a setting that lets you past a check UMH Core makes. Some paths depend on one: where a path exists only because a check can be switched off, the page that describes the path names the setting that opens it.

An escape hatch stays available for as long as the check exists. While one is set, the instance tells you so, so that it does not stay set by accident. [Turn off bridge admission](usage/data-flows/bridges-do-not-start.md) is one.

## Early access features

An early access feature is a product feature we are still finishing. It can change or break without notice, and you switch it on yourself under **Settings**, **Early Access Features** in the [Management Console](management-console/README.md).

An early access feature will become the intended way to do its job. A supported or provisional path will not, however long we keep it working. Weigh that when you decide what to build on.
