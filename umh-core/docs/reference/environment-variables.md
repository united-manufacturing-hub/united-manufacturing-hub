# Environment Variables

This is the reference for all environment variables used by umh-core. These variables override or supplement configuration from `config.yaml`.

| Name             | Values                                                                 | Description                                          |
| ---------------- | ---------------------------------------------------------------------- | ---------------------------------------------------- |
| LOGGING\_LEVEL   | ERROR, WARN, INFO, DEBUG                                                      | Controls log verbosity. DEBUG shows detailed internal operations |
| AUTH\_TOKEN      | (Base64 encoded token)                                                 | Management Console authentication token. Overrides auth token from config.yaml |
| API\_URL         | https://management.umh.app/api, https://staging.management.umh.app/api | Management Console API endpoint. Use staging for testing environments |
| RELEASE\_CHANNEL | enterprise, stable, nightly                                            | Release channel reported to the Management Console, which compares the instance's version against it. umh-core does not update itself. Enterprise = most stable, nightly = latest features |
| S6\_PERSIST\_DIRECTORY | true/1/TRUE/True, (unset/false/other)                           | Controls S6 service directory persistence. Truthy values (true, 1, TRUE, etc.) = /data/services (persist across container restarts for debugging). Default/false = /tmp/umh-core-services (cleared on container restart for fresh state) |
| USE\_CANONICALIZE\_FAST | 0, 1, false, true (default: 1) | Compares a bridge's desired and running configuration by walking the values directly. Set to 0 and restart the container to fall back to the slower YAML round-trip, the reference implementation, if a configuration is ever reported as changed on every tick. The value is read as a boolean, so `1`/`0`, `true`/`false` and `t`/`f` all work in any capitalization; anything else falls back too, and logs a warning naming what was set |
| USE\_FSMV2\_CPU | false, 0, no, n, off (any case) turn it off; unset or any other value leaves it on (default: on) | Selects the [CPU health check](../usage/instances/container/cpu-health/README.md) for the CPU status. Set it to `false` to use the 70% CPU usage rule instead. Read once at startup, so changing it means recreating the container, because `docker restart` keeps the old environment. See [Which framework runs a component](../usage/instances/agent/metrics.md#which-framework-runs-a-component) |
| LOCATION\_<0-6>  | (string values)                                                        | Sets Agent location path levels 0-6. Example: LOCATION_0=factory, LOCATION_1=line1 |
| HTTP\_PROXY, HTTPS\_PROXY, NO\_PROXY | Proxy URL, for example `http://proxy.company.com:8080`; `NO_PROXY` takes a comma-separated host list | Proxy for outbound connections. Lowercase variants work too. See [Network Configuration](../production/security/umh-core/network-configuration.md#proxy-configuration) |
| SSL\_CERT\_DIR | Directories separated by `:`, for example `/etc/ssl/certs:/certs` | Directories from which umh-core loads additional trusted CA certificates in PEM format. Needed behind a firewall that inspects TLS. See [Instance Stays Offline Behind a Corporate Firewall](../usage/instances/communicator/instance-offline-behind-corporate-firewall.md#add-your-corporate-ca-to-the-container) |
| NMAP\_BACKEND | (any value) | Ignored. Connection checks always run on FSMv2, and the FSMv1 fallback is gone. Remove the variable from your `docker run` command. See [Which framework runs a component](../usage/instances/agent/metrics.md#which-framework-runs-a-component) |
